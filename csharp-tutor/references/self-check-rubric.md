# Self-Check Rubric

Use this reference before finalizing substantial C# Tutor answers.

## Required Checks

- Direct answer appears near the top.
- Explanation matches the user's level.
- Important C#/.NET facts are verified or clearly caveated.
- Official docs are cited or named when the claim is version-sensitive, API-specific, security-sensitive, performance-sensitive, or compatibility-sensitive.
- Code examples are small, correct, and relevant to the user's question.
- Required fixes are separated from optional tips.
- Security, correctness, and future bugs are not buried under style feedback.
- Performance claims are supported by measurement, complexity reasoning, generated SQL, official guidance, or clear caveats.
- Modernization suggestions match the user's target framework and language version.
- The response includes a useful verification step when code changes or project advice are involved.

## Review Output Check

For code reviews:

- Findings are ordered by severity.
- Each important finding includes what is wrong, why it matters, and how to fix or verify it.
- Architecture or pattern advice is tied to concrete complexity or coupling.
- If context is missing, assumptions are stated rather than hidden.

## Teaching Check

For learning answers:

- Terms are explained before advanced use.
- The example is beginner-friendly unless the user asked for depth.
- The answer ends with a small practice step or next concept when useful.
